# RXS Recorder — Android prototype (Phase 2a)

Recorder-**only** prototype for the "RXS Camera + Scorer" companion. **No scoring yet**
(that's Phase 6). Goal: capture rear-camera video + mic, honestly report the device's
real capabilities, and save a clean clip to the Gallery — so we can run the Phase 3–5
device comparison on real Beyblade battles.

## What it does
- **Runtime capability query** (Camera2): supported video sizes + true per-size max FPS
  (from min frame duration), AE FPS ranges, HDR10 flag, stabilization modes, and
  high-speed/slow-motion modes **listed separately** (never used for normal recording).
- **Honest profile selection:** 4K/60 → 1080p/60 → 1080p/30 → largest-available.
- **Review last clip:** after Stop, **▶ REVIEW LAST** opens the clip with play/scrub +
  **frame-by-frame** stepping (ExoPlayer EXACT seek), then Close back to the camera.
- **Records** via CameraX `Recorder`/`VideoCapture` with the chosen profile, AE FPS pinned.
- **Saves clean MP4** to `MediaStore` → **Gallery → Movies/RXS** (normally shareable to
  TikTok/IG/YouTube; the saved file is the camera stream only — overlay is never burned in).
- **HUD overlay:** REC timer, requested + negotiated resolution, mic state, free storage.
- **Controls:** tap-to-focus, pinch-to-zoom. Orientation locked landscape. Screen kept awake.
- **Detects:** low storage (warn <1 GB, block start <200 MB), recording/finalize errors,
  mic state.

## Build & run
1. Open `companion/android/` in **Android Studio** (Koala/Ladybug+). Let Gradle sync; accept
   any AGP/Kotlin upgrade prompts. (The Gradle wrapper jar is generated by Studio on first
   sync, or run `gradle wrapper`.)
2. Connect a device (USB debugging) — **start with the HONOR X7d**. Run the `app` config.
3. Grant Camera + Microphone when prompted.

> Built on Windows without the Android SDK, so it was **not compiled here** — first build
> happens in your Android Studio. If AS flags the `LocalLifecycleOwner` import, accept its
> quick-fix to `androidx.lifecycle.compose.LocalLifecycleOwner`.

## Phase 3–5 — what to measure on-device (for the test report)
Record a real battle and compare against the stock Camera app:
- Selected vs **actual** resolution/FPS — verify the file with `ffprobe`/MediaInfo
  (`ffprobe -show_streams clip.mp4`). Confirm no silent downgrade.
- **HONOR X7d expectation:** normal record likely **1080p/30** even though the stock Camera
  has a separate slow-mo mode — confirm the CAPS dump reflects that and we don't claim 60.
- Dropped frames, focus/exposure behavior, stabilization, **audio sync** over a 10-min clip,
  device heat, storage use, and that the clip opens in Gallery and **shares normally**.
- Document HONOR results separately from iPhone.

## Known limitations (prototype)
- Exposure lock + stabilization toggle not yet exposed in UI (capabilities are queried;
  controls land with the scoring build). Tap-focus + pinch-zoom only for now.
- "Actual FPS" is set from the requested AE range; ground truth comes from the file in Phase 4.
- Review covers the **last** clip; a full multi-clip in-app gallery is still later (Phase 8).
